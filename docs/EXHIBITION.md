# FIELDWEAVER exhibition workbench

This is a noncanonical *selection UI* over immutable accepted recipes, with an explicit canonical CPU preview/export action. It does not register new recipes, extend the simulation model, or change the renderer's source of truth.

## User workflow

1. Launch FIELDWEAVER normally. The sidebar **Exhibition · accepted presets** panel exposes the four FW-014 release presets in a two-column grid. Select with mouse, Tab/Enter/Space, the native selector, or Previous/Next. Selection only updates descriptive metadata; it never replaces in-progress work.
2. Inspect the exact source recipe hash, unsigned root seed, target tick, fixed crop and lineage parent (where present). These values come from the accepted preset catalog, not from live editor state.
3. Choose **Render canonical proof**. The panel calls the existing `createCanonicalExport` CPU replay/software raster at the accepted tick and crop (96×64 pixels for the current built-ins), with explicit capacities 4096 agents and 250,000 deposition records and 32×32 raster tiles. No WebGL screenshot, Canvas2D sampling, stock thumbnail, external service, or noncanonical proxy is involved. The generated PNG and raw RGBA hash are only shown after replay completes.
4. Download **proof PNG** and **provenance** for a genuine, reproducible pair. The provenance includes the complete normalized recipe, seed, replay hashes, tick, crop, lineage and canonical decoded RGBA8 hash. PNG byte identity is not the canonical oracle.
5. Choose **Save selected recipe** to download the exact accepted normalized `.fwrecipe.json` without first replaying a proof or changing the current working editor. It uses the same versioned file format as **Recipe persistence → Load recipe**, with the accepted recipe hash in its filename. The gallery checks a parse/serialize/hash roundtrip before offering the download, and refuses missing or unaccepted IDs. The downloaded recipe contains the seed, fields, emitters, materials, LUT and timeline commands, but the *exhibition-specific* target tick and proof crop are separate catalogue metadata displayed in the gallery. For the full replay settings and exact CPU image identity, first render the proof and download its **provenance** sidecar. Browser download delivery is managed by the user agent; this button does not assert filesystem persistence.
6. Select **Load preset** to transactionally adopt the accepted recipe into the editor. This is the only gallery action that replaces live work. It also copies the accepted crop and target tick into the existing **Canonical export** controls where available. Run that existing export panel to reproduce the larger workflow.
7. Switching entries immediately invalidates any prepared gallery proof and disables the prior PNG/provenance download buttons; no previous image may be presented as the new entry's export.

8. To compare real artworks, **Render canonical proof** for the first composition, then choose **Pin rendered proof as A**. Select another accepted composition and render its proof. The two labelled frames display independent, actual CPU-rendered PNGs plus each work's seed, tick, crop, recipe hash and raw decoded RGBA8 identity. A persists while browsing and B is always the current selection's freshly rendered proof; navigation immediately clears stale B. **Download A PNG / provenance** remains available while A is pinned. **Clear A** releases the pinned URL and disables its downloads. The comparison reports identity equality/difference and whether authored crops match; it is **not** an inferred visual-similarity score, synthetic difference image or cross-work resampling.

## Scope and integrity

The gallery currently enumerates **only the four immutable built-in release presets**. New original or mutated artwork must not be advertised as accepted merely because an unmerged gallery branch exists; Integration must review its recipe, licensing/provenance, deterministic replay and admission first. Catalog expansion is a separate guarded deliverable.

`src/ui/exhibition-catalog.js` is a read-only adapter over `src/presets/catalog.js`. The authoritative export remains `src/export/package.js` and `docs/EXPORT.md`; the 96×64 accepted raster results are locked by `fixtures/fw-014-presets.json`. `tests/exhibition.test.mjs` verifies navigation, recipe immutability, exact golden software-raster hashes, PNG decode equality and provenance. The release browser smoke exercises real DOM selection/rendering and ensures stale proofs are invalidated. It also pins the first golden-rendered work, navigates to a second, renders an independent B, inspects both image sources/metadata, invalidates B on further navigation and clears A. The Chrome/Firefox CI workflow archives a real two-up screenshot as `release-exhibition-<browser>.png`; layout inspection remains distinct from deterministic tests.

**Browser CSP:** gallery PNGs are local `blob:` object URLs produced from actual canonical export bytes. both `index.html` and the local server's HTTP security header explicitly permit `blob:` in **image sources only**; remote resources, scripts, navigation and telemetry remain disallowed. Browser smoke verifies nonzero decoded 96×64 PNG dimensions, not merely image visibility flags or matching hashes.

**Accessibility:** native buttons/select, visible focus outlines, aria-pressed single selection, described selection metadata, and live status; no auto-playing animation or network activity.

**Limitations:** proof generation runs on the main thread after one animation frame so it is synchronous canonical replay, not a continuously updating live thumbnail. The small 96×64 raster is a validation preview; users can increase output resolution through canonical export, but changing the crop or scale produces a different canonical pixel hash. No gallery screenshot or aesthetics claim is made without browser rendering evidence.

## Larger proof inspection

Once a CPU proof has rendered, choose **Inspect larger / compare**. A native modal dialog presents the existing canonical PNG at a larger fitting size, or at exact 2×, 4× and 8× nearest-neighbour display scale. This is strictly a *view transform* of the original PNG object URL: the CPU raster, recipe, tick, crop, and decoded RGBA8 identity are not recomputed or altered. The frame lists the seed, recipe identity and raw-pixel hash.

If a proof is pinned as A and another proof is rendered as B, the dialog presents both independent outputs side by side. Without a pinned proof, it displays the current proof alone. When A is pinned but B has not been freshly rendered, it displays A alone. Press **Escape** or the **Close inspection** button to return to the editor; selection, re-render or unpin closes an open inspector before any PNG object URL is revoked, preventing stale or mislabelled images. Controls are native buttons/select/dialog and remain keyboard operable. This inspector does not inspect unmerged artwork, upscale canonical resolution or assert inferred aesthetic similarity.
